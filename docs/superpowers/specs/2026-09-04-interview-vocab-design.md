# 면접 단어 (「면접」 등급) 설계

2026-09-04

## 무엇을 만드는가

`vocab.tsv`에 250줄을 더해, 등급 줄에 `N5 · N4 · N3 · N2` 다음으로 **「면접」**
칸이 하나 생긴다. 일본 회사 프론트엔드 면접에 실제로 나오는 말이다.

```
단어 맞추기
┌────┬────┬────┬────┬──────┐
│ N5 │ N4 │ N3 │ N2 │ 면접 │
└────┴────┴────┴────┴──────┘
  전체          250장
  프론트 용어    55장
  업무 시스템    55장
  개발 현장      50장
  면접 표현      50장
  경어·매너      40장
```

## 왜 이렇게 만드는가

**목표는 특정 면접이다.** ネゾット株式会社(NEZOT) 프론트엔드 지원이 전제다.
회사를 알아보고 짠 단어라, 「일본어 IT 단어장」이 아니다.

- 도쿄증권 프라임 상장 **WDB홀딩스** 그룹사. 그룹 9개사의 DX를 플랫폼으로 민다
- **受託·SES가 아니라 自社開発** — 개발·운영·보수를 자사에서 일관되게 한다
- 만드는 것: `ドコ1`(인재파견 일원관리) · `doconico`(파견 수속 페이퍼리스) ·
  `CoCoPos`(제조판매후조사 PMS)
- 즉 **B2B 업무 시스템**이다. 인재파견과 의료·제약 도메인
- 공고의 스택은 PHP(Laravel) · JavaScript(Vue.js) · SQL

그래서 단어의 결이 이렇게 갈린다:

- **`管理画面`·`一覧`·`帳票出力`·`権限`·`入力チェック`·`必須項目`** 가 실무어다.
  애니메이션·표시속도·픽셀 완성도 쪽이 아니다. B2B 업무 시스템의 프론트엔드는
  대부분 관리 화면이다.
- **`派遣`·`勤怠`·`請求書`·`発注`·`受注`·`一元管理`** 를 넣는다. 저 제품 소개
  페이지를 읽을 수 있게 되는 말이다 — 志望動機와 逆質問이 여기서 나온다.
- **`自社開発`** 이 면접 표현의 핵심 단어다. 受託·SES와 대비되는 지원 이유가
  이 회사에서 가장 자연스러운 답이다.
- Vue 쪽 말(`双方向`·`単一ファイル`·`算出プロパティ`)을 쓰고 React 고유어
  (`仮想DOM`·`副作用`)는 안 쓴다.
- Laravel·SQL이 공고에 같이 적혀 있으므로, 프론트만 하는 사람도 물리는
  `連携`·`疎通`·`抽出`·`整合性` 정도는 넣는다.

## 데이터가 거의 전부다

`app/src/main/resources/vocab.tsv`에 250줄. 8칸 형식은 그대로다.

```
표기 · 읽기 · 뜻 · 분류 · 등급 · 예문 · 예문읽기 · 예문뜻
```

등급 칸에 새 값 `JOB`이 들어간다. 분류는 위 다섯 개.

**표제어는 단어, 예문은 실전 문장이다.**

```
志望動機  しぼうどうき  지망 동기  면접 표현  JOB
志望動機を教えてください。
しぼうどうきをおしえてください。
지망 동기를 말씀해 주세요.
```

이렇게 두면 문장 맞추기가 `＿＿＿を教えてください` 를 내고, 예문 조각을 누르면
`教える`의 뜻이 붙는다. 표제어를 구절(`御社の〜に魅力を感じました`)로 두면
그 둘이 다 깨진다.

예문을 더했으므로 `tools/tokens.sh`를 한 번 돌려 `tokens.tsv`를 다시 만든다.

### 데이터가 통과해야 하는 제약

새로 만들 검사가 아니라, **이미 있는 검사가 요구하는 것**이다. 250줄을 쓰는
내내 지켜야 한다.

1. **표기가 기존 5,171개와 겹치면 안 된다.** 카드 열쇠가 `V` + 표기라
   (`Word.id`) 겹치면 SRS 기록이 한 칸에 섞인다. `会社`·`経験`·`説明`처럼
   이미 있는 말은 뺀다. `DataTest`의 「카드 열쇠가 전부 다르다」가 잡는다.
2. **읽기는 가나만, 비어 있으면 안 된다.** 가타카나 표제어는 표기를 그대로
   반복한다 (`コンポーネント` → `コンポーネント`). 기존 `トイレ`가 그 결이다.
3. **예문읽기에 표제어 읽기가 그 횟수만큼 들어 있어야 한다.** 안 그러면
   문장 맞추기 통에서 조용히 빠진다 (`Cloze.readable`). 빠져도 테스트는
   통과하므로 눈으로 챌 수 없다 — 이게 제일 새기 쉬운 자리다.
4. **예문의 가타카나는 예문읽기에도 가타카나로.** `フロントエンド`를
   `ふろんとえんど`로 적으면 외래어를 히라가나로 쓰는 줄 가르친다.
5. **예문에 표제어(또는 어간)가 실제로 들어 있어야 한다.**
6. **같은 분류 안에 뜻이 똑같은 말이 셋 이상 몰리면 안 된다.** 4지선다 오답
   후보를 같은 분류에서 먼저 뽑는데, 동의어는 후보에서 빠지기 때문이다.
   `ご確認`·`ご対応`·`ご返信`의 뜻을 다 「부탁드립니다」로 적으면 후보가 모자란다.
7. **표기·읽기·예문에 라틴 문자와 숫자를 못 쓴다.** 읽기 칸은 가나만 받는
   정규식으로 검사하고(`DataTest.kanaOnly`), 예문 읽기도 같은 규칙이다.
   그래서 `CSV出力`·`API連携`·`仮想DOM`은 표제어가 될 수 없다 — 각각
   `帳票出力`·`連携`으로 바꾸고 `仮想DOM`은 뺐다.

## 코드는 두 자리

### 1. `Jlpt` → `Level` 리네임 + 멤버 하나

```kotlin
enum class Level(val label: String) {
    N5("N5"), N4("N4"), N3("N3"), N2("N2"), JOB("면접")
}
```

**타입 이름을 바꾸는 이유**는 「면접」이 JLPT 등급이 아니기 때문이다.
`Jlpt.JOB`은 이름이 거짓이 된다. tsv에 적히는 값(`N5`·`JOB`)은 안 바뀌므로
데이터는 손대지 않고, 타입 이름만 기계적으로 옮긴다 — `Kanji.kt` · `Vocab.kt` ·
`Cloze.kt` · `WordQuizScreen.kt` · `ClozeScreen.kt`와 테스트 둘(`DataTest` ·
`ClozeTest`). `Level`이라는 이름은 지금 코드에 없어 충돌하지 않는다.

**멤버 이름을 `JOB`으로 두는 이유**는 담는 것이 면접 표현만이 아니기 때문이다
(업무 시스템어·경어까지 든다). 화면에 뜨는 말은 `label`인 「면접」이다.

`JOB`을 맨 뒤에 두는 것도 뜻이 있다. `VocabData.byKanji`가 `level.ordinal`로
정렬해서 한자 정답면의 「든 단어」 줄을 세우는데, 그 한자를 이제 만난 사람에게
면접 단어가 먼저 보일 이유가 없다.

### 2. 한자 맞추기 등급 줄에서 「면접」 감추기

`kanji.tsv`에는 `JOB` 줄이 없다. 그대로 두면 한자 맞추기에 눌러도 빈 탭이
하나 뜬다. `WordQuizScreen.kt`의 세그먼트를 데이터로 거른다.

```kotlin
options = Level.entries.filter { kind != CardKind.KANJI || KanjiData.of(it).isNotEmpty() },
```

등급 이름을 코드에 박지 않는다 — 한자표에 그 등급 줄이 생기면 탭도 저절로 돌아온다.

## 저절로 따라오는 것

나머지는 **코드 0줄**이다. 다 `VocabData`를 읽기 때문에 등급 탭도 분류 목록도
데이터에서 뜬다.

| 자리 | 어떻게 |
|---|---|
| 단어 맞추기 | 뜻↔표기↔읽기 세 방향, 4지선다 오답까지 |
| 문장 맞추기 | `Cloze.pools`가 `Level.entries`를 돌아 통을 만든다 |
| 스피드 | 한 번 맞힌 단어가 자동으로 든다 |
| 찾기 | 표기·읽기·뜻으로 다 걸린다 |
| 오답 노트 · SRS · 백업 | 열쇠가 `V`+표기라 기존과 같은 길 |
| 예문 조각 누르기 | `tokens.tsv`를 다시 만들면 조각마다 뜻이 붙는다 |
| 홈 익힘 비율 | 분모가 5,171 → 5,421이 된다 (아래) |

`SegmentedRow`는 칸마다 `weight(1f)`라 5칸도 폭을 고르게 나눈다. 「면접」은
두 자라 13sp에서 넉넉하다.

## 넣지 않는 것

- **설정 토글을 안 만든다.** 면접 카드를 익힘 분모에서 뺄 스위치는 없다.
  분모가 250장 늘어 홈의 익힘 %가 내려가는 것을 받아들인다. `Store`·`cardIds`·
  설정 화면·테스트까지 달리는 값이고, 면접 준비가 목적인 사람이 그 카드를
  분모에서 뺄 이유가 없다. 나중에 필요하면 `한자` 토글 옆에 한 줄 더 붙인다.
- **별도 덱·홈 타일을 안 만든다.** 「요즘 쓰는 말」처럼 따로 살면 화면·SRS
  열쇠·백업을 새로 만들어야 하고, 얻는 것은 홈 타일 한 칸이다.
- **면접용 한자 데이터를 안 넣는다.** 한자표는 JLPT 등급 체계 그대로 둔다.
- **단어를 앱에서 직접 추가하는 화면을 안 만든다.** 학습 데이터는 소스가 아니라
  tsv에 있고, 고칠 사람은 이 저장소를 가진 한 사람이다.

## 테스트

기존 테스트가 세는 수를 고친다. CLAUDE.md가 「줄을 고치면 `DataTest`의 등급별
개수도 같이 고쳐야 한다」고 적어 둔 그 자리다.

| 파일 | 무엇 |
|---|---|
| `DataTest` | 등급별 개수에 `JOB` 한 줄, `VocabData.all` 5171 → 5421 |
| `ClozeTest` | 통 크기에 `JOB` 한 줄, `Cloze.total` 갱신 |
| `TokensTest` | 조각 수·내용어 수 갱신. 뜻 붙는 비율 78% 유지 확인 |

새로 하나 더한다:

- **「면접 등급에는 한자 카드가 없다」** — 한자 탭에서 감추는 필터의 근거다.
  `KanjiData.of(Level.JOB).isEmpty()`. 나중에 한자표에 `JOB` 줄을 넣으면
  이 테스트가 먼저 터져서, 필터를 다시 볼 자리를 알려 준다.

`TokensTest`의 「내용어 대부분에 뜻이 붙는다」는 78% 하한이다. 면접 단어의
예문에는 우리 단어표에 없는 말(`御社`의 예문에 드는 존경어 활용 등)이 섞이므로
비율이 내려갈 수 있다. **내려가면 하한을 낮추지 않고 예문을 고친다** — 뜻이
안 붙는 조각이 많으면 조각을 눌러도 아무것도 안 뜬다.

## README

`README.md`의 구성 표(단어 수·등급)와 테스트 개수를 고친다. 메뉴 순서·기능
번호·홈 타일 수는 안 바뀐다 — 화면을 더하지 않기 때문이다.

## 못 미더운 곳

**250줄의 품질은 기계가 못 본다.** 뜻이 맞는지, 경어가 실제로 그 자리에 쓰이는
말인지는 검사가 아니라 사람이 본다. 경어는 특히 틀리면 면접에서 손해다.

그래서 **분류별로 다섯 덩이로 나눠 넣고, 덩이마다 사람이 훑는다.** 한 번에
250줄을 검토할 수는 없다. 덩이 순서는 확인이 쉬운 쪽부터:

1. `프론트 용어` 55 — 아는 개념의 일본어 이름이라 제일 검토가 쉽다
2. `업무 시스템` 55 — 화면 요소어 + 파견 도메인어
3. `개발 현장` 50
4. `면접 표현` 50
5. `경어·매너` 40 — 제일 틀리기 쉬워 마지막에, 가장 천천히

덩이마다 `./gradlew testDebugUnitTest`를 돌리고, **그 덩이에서 수를 세는 테스트도
같이 맞춘다.** 마지막에 한 번에 맞추려면 덩이 넷 동안 테스트가 빨간 채로 남는데,
그러면 덩이 사이에서 「내가 방금 깬 것」과 「원래 깨져 있던 것」이 안 갈린다.
값은 손으로 세지 않고 테스트가 낸 실패 메시지의 실제 수를 넣는다.

**확인해 볼 것 하나.** Green 공고의 근무지가 효고현으로 뜬다(WDB 본거지가
히메지다). 마루노우치 본사와 다르니 지원 전에 볼 값이다. 단어와는 무관하다.
