# 문장 맞추기 (빈칸 채우기) 설계

2026-09-04

## 무엇을 만드는가

예문에서 표제어 한 개를 `___`로 가리고, 그 자리에 들어갈 단어를 넷 중에서
고르는 판. 기존 기능 여섯째로 붙는다.

```
N5  N4  N3  N2
────────────────────
7 / 20        연속 4

    ___で行きます。

  電気  ·  電車  ·  自動車  ·  自転車
```

## 왜 만드는가

이미 갖춘 것으로 새 놀이가 하나 나온다. `vocab.tsv`의 예문 5,171개가 지금은
정답면 한 줄로만 쓰이고 있고, 오답 후보를 뽑는 `VocabData.distractors`와 정답면
전체를 그리는 `Face.kt`가 그대로 재사용된다. 새로 쓰는 것은 화면 한 장이다.

목적은 정착률이 아니라 **재미**다. 지금 익히는 자리들은 카드 한 장을 떼어 놓고
묻는데, 이 판만 문장 안에서 묻는다. 오답 세 개도 채점 뒤 뜻이 붙어 노출 세 번이
된다.

## 자리와 화면 흐름

`Feature.CLOZE("문장 맞추기")`를 `SELF` 다음에 끼운다. 드로어와 홈 타일이
`Feature.entries`를 돌기 때문에 목록에 자동으로 따라온다.

```
오늘 · 가나 맞추기 · 한자 맞추기 · 단어 맞추기 · 문장 맞추기 · 스피드 · 오답 노트
```

**한 단계다.** `Screen.Menu(CLOZE)`만 쓰고 `Screen.Practice`는 쓰지 않는다 —
범위가 JLPT 등급 하나뿐이라 목록 화면을 따로 두면 세그먼트 한 줄을 보러 화면을
한 장 더 넘기게 된다. 등급은 화면 맨 위 `SegmentedRow`이고, 바꾸면 판이 새로
깔린다. 뒤로가기는 홈으로 간다.

## 카드 통

```kotlin
VocabData.of(level, VocabData.ALL_TAGS).filter { it.w in it.ex }
```

표기가 예문에 **통째로** 든 단어만 쓴다.

| 등급 | 쓸 수 있는 단어 | 전체 |
|---|---:|---:|
| N5 | 596 | 710 |
| N4 | 506 | 653 |
| N3 | 1,730 | 2,062 |
| N2 | 1,499 | 1,746 |

`Word.stem()`을 쓰면 5,171개 전부에서 표제어를 찾을 수 있고 `DataTest`가 이미
그것을 보장하지만, 어간은 마지막 글자를 떼기 때문에 어간만 가리면 남은 글자가
빈칸 밖으로 샌다 — `友達` → `___達と映画を見ます`. 그래서 활용형 400여 개는
뺀다. 등급마다 500장이 넘어 20장짜리 판에는 넘친다.

## 한 장

**문제면** — `w.ex.replace(w.w, "___")`. 빈칸은 표기 길이와 무관하게 고정 세
글자다. 길이만큼 칸을 그리면 몇 글자인지가 힌트로 샌다. 표기가 예문에 두 번
나오는 단어 26개(`歌`·`北`·`千`·`日`·`百` 등)는 두 자리가 다 가려진다.

**보기** — `(VocabData.distractors(w) + w).shuffled()`를 표기로 세운다. 카드마다
한 번만 뽑아 `remember`에 담는다 — 그리는 중에 뽑으면 재그리기마다 순서가 바뀐다
(`WordSpeedBody`가 같은 이유로 그렇게 하고 있다).

**채점** — 누르는 순간 판정한다. 「정답 확인」 단추가 없다 — 보기를 누르는 것이
곧 답하는 것이다. 정답 칸은 초록, 고른 오답은 붉게 남고, `Verdict`가 카드
흔들림과 번쩍임을 그대로 맡는다.

**정답면** — `AnswerFace(saysOf(w), linksOf(w), speaker)` 한 줄로 읽기 · 예문
세 줄(일본어 · 읽기 · 한국어 뜻) · 든 한자 칩이 줄마다 재생 단추까지 달고 붙는다.
단어 맞추기와 오답 노트가 쓰는 것과 같은 정답면이다.

**보기 넷은 채점 뒤에도 그 자리에 남고 각자 뜻이 붙는다.** 오답도 뜻을 보여
주는 것이 이 판의 값어치 절반이다 — `distractors`가 같은 분류에서 뽑으므로
네 개가 한 계열로 묶여 나와서, 한 문제에 비슷한 말 넷을 나란히 보게 된다.

**다음 장** — 정답면이 펼쳐진 채로 「다음」 단추가 뜬다. 자동으로 넘기지 않는다 —
정답면을 읽는 것이 이 판에서 실제로 배우는 자리다.

## 한 판

20장. 위에 `7 / 20`과 이번 판 연속 정답 수가 선다. 다 넘기면

```kotlin
CycleDone("맞음 17 / 20 · 최고 연속 6", "홈으로", onBack, "다시", onRestart)
```

## 기록을 남기지 않는다

`Store`도 `Srs`도 건드리지 않는다. 최고 점수조차 저장하지 않는다.

사지선다는 보기에서 답을 역추적할 수 있어서, 이것을 복습 일정에 흘리면 찍어서
맞힌 카드가 익힘으로 오른다. 단어 맞추기를 직접 채점으로 둔 이유가 그것이고,
스피드를 아예 다른 메뉴로 뺀 이유도 같다. 이 판은 스피드 쪽이다.

최고 점수를 안 남기는 것은 스피드와 다른 점이다. 스피드는 「1분에 몇 장」이
재는 값 자체라 남길 것이 있는데, 여기는 20장 중 몇 개가 판마다 어느 단어를
뽑았는지에 좌우되어 판끼리 견줄 수 없다. 남기면 뜻 없는 숫자가 하나 는다.

홈 타일에 붙는 글도 그래서 기록이 아니라 통 크기다 — 「예문 4,331개에서 뽑습니다」.

## 애매한 문제가 나온다

오답이 같은 분류에서 나오기 때문에 빈칸에 여럿이 문법적으로 들어맞는 문제가
섞인다 — `___で行きます` 에는 `電車`·`自動車`·`自転車`가 다 들어간다. 문장을
파싱하지 않으면 데이터로 막을 수 없고, 파서를 넣는 것은 이 기능의 값어치에
비해 너무 크다.

그대로 두기로 한다. 기록을 안 남기니 틀려도 잃는 것이 없고, 채점 뒤 넷의 뜻을
다 보게 되므로 애매한 문제도 노출로는 온전히 값을 한다.

대신 **왜 그런지는 알려 준다.** 상단 바 ⓘ를 이 화면에서도 띄우고, 눌렀을 때
이 판 전용 설명을 낸다.

> 문제는 예문에서 단어 하나를 가려 자동으로 만듭니다. 그래서 빈칸에 두 개
> 이상이 들어맞는 문제가 섞일 수 있습니다. 이 판은 복습 기록에 남지 않으니
> 틀려도 잃는 것이 없고, 채점하면 고르지 않은 보기의 뜻도 함께 보여줍니다.

ⓘ는 지금 `App.kt` 상단 바에서 홈에만 뜨고 `SrsExplainer`를 연다. 조건을
「홈 또는 문장 맞추기」로 넓히고, 어느 설명을 열지 한 줄로 가른다. ⓘ를 찾는
자리가 화면마다 다르면 안 되므로 화면 안에 따로 두지 않는다.

## 손대는 곳

| 파일 | 하는 일 |
|---|---|
| `ui/ClozeScreen.kt` | 새 파일. 화면 한 장과 ⓘ 설명 |
| `ui/App.kt` | `Feature`에 한 줄, `when`에 한 줄, ⓘ 조건 한 줄, 홈 타일 한 칸 |
| `ui/Theme.kt` | 강조색 `sora` 추가 (밝은 쪽·어두운 쪽 한 줄씩) |
| `ui/Parts.kt` | `rememberVerdict`의 `private` 떼기 |

`Theme.kt`에 색을 더하는 이유는 지금 강조색이 다섯 개(`shu`·`ai`·`ok`·`gold`·
`murasaki`)이고 홈 타일 다섯 장이 하나씩 다 쓰고 있어서다. 타일 색이 곧 기능
표시라 여섯째가 색을 나눠 쓰면 그 구실이 깨진다. `sora`(하늘빛) 한 개를 밝은
쪽·어두운 쪽에 한 줄씩 더한다 — 실제 값은 기존 다섯과 눈에 갈리는 선에서 같은
채도대로 잡는다.

`rememberVerdict`는 `Parts.kt`에서 파일 private이라 새 파일에서 부를 수 없다.
`private`만 뗀다 — 같은 패키지 안이고 이미 `Verdict`와 `shakeKey`는 공개다.

**데이터 · `Srs` · `Store` · `Face.kt`는 건드리지 않는다.**

## 검사

`DataTest`에 한 줄을 더한다.

- 등급마다 쓸 수 있는 단어가 20장(한 판)을 넘는지
- 표기를 `___`로 갈아 낀 뒤 문장에 그 표기가 남지 않는지 — 통을 `it.w in it.ex`로
  걸렀으므로 `replace`가 반드시 지운다. 이 검사가 통 필터와 치환이 어긋나는 것을
  잡는다.

`ClozeScreen`은 Compose 화면이라 단위 테스트를 붙이지 않는다. 판정에 쓰는 계산이
`choice.w == answer.w` 한 줄이라 검사할 로직이 통 필터와 빈칸 치환뿐이고, 둘 다
`DataTest`가 데이터 전체에 대고 확인한다.

## 일부러 안 하는 것

| 안 하는 것 | 이유 |
|---|---|
| 타이머 | 문장을 읽어야 하는 판에 시간을 걸면 읽지 않고 찍는다. 시간을 재는 자리는 스피드다 |
| 분류(`사물`·`동사`…)로 범위 좁히기 | 기록을 안 남기니 범위를 좁힐 이유가 없다. 고를 자리만 는다 |
| 활용형 단어 되살리기 | 어미가 빈칸 밖으로 샌다. 통이 등급마다 500장을 넘어 되살릴 필요가 없다 |
| 예문 한국어 뜻을 미리 보여주기 | 답이 그대로 드러난다. 정답면에서 본다 |
| 최고 점수 저장 | 판마다 뽑는 단어가 달라 견줄 수 없는 숫자다 |
| 한자 문장 판 | `kanji.tsv`의 예시는 단어 하나(`電車`)이고 문장이 아니다. 가릴 문장이 없다 |
