# 하루 목표 설계 — 새 단어 N개 하나로 줄인다

2026-09-14

## 무엇을 고치는가

설정의 「한 묶음 구성」 슬라이더 셋(`새 카드` · `복습 카드` · `익히는 중 상한`)을
**「하루 새 단어」 하나로** 줄인다. 그 값 하나가 하루 공부를 정한다 — 새 단어 N개가
나오고, 복습은 오늘 나올 것이 다 나온다.

```
설정 ─ 하루 목표
  하루 새 단어  [────●─────]  20장

  손에 쥐는 카드 ~200장 · 하루 푸는 장수 ~220장
  남은 단어 1,150개를 58일에 끝냅니다.
```

## 왜 고치는가

### 1. 지금 설정은 하루를 말하지 않는다

`새 카드 5` + `복습 20` = 25는 **한 묶음**(한 자리에 낼 장수)이지 하루 몫이 아니다.
「한 바퀴 더」를 누르면 또 25장이 나온다. 사용자가 정하고 싶은 것은 "오늘 몇 개
배우나"인데 설정에는 그 자리가 없다.

### 2. 상한이 하루 2장으로 목을 조르고 있다

계산이 맞지 않는다:

- 익힘 문턱은 `MASTERED_AT = 10`점이고, 점수는 **하루 한 번만** 오른다(`isDoneToday`).
  → 카드 한 장이 익힘까지 **최소 10일**.
- 「익히는 중 상한」 20장이면 익힘에 오르는 속도가 `20 ÷ 10일` = **하루 2장**.
  상한은 문이라 자리가 비는 만큼만 새로 트므로 **새 단어도 하루 2장**이다.
- 기본값 「새 카드 5장」은 처음 나흘만 유효하다. 그 뒤로는 상한이 문을 닫는다.

남은 단어 1,150개를 하루 2장이면 **575일**이다. 시험은 2026년 12월 초, 오늘부터
**80일 남았다.** 지금 설정으로는 시험 전에 절반도 못 뗀다.

### 3. 브레이크가 둘이면 작은 쪽만 남는다

하루 몫 N이 진짜 상한이면 「익히는 중」은 저절로 `N × 10`에서 평형이 된다 — 하루
N개가 들어와 10일 만에 졸업하므로 손에 쥔 장수가 그 이상 안 는다. 여기에 상한을
또 두면 늘 작은 쪽이 이겨서, 사용자가 고른 N이 조용히 무시된다. **상한은 하루
몫이 없던 시절의 대타였다.** 진짜가 오면 물러날 자리다.

### 4. 하루 한 판이 이미 있다

`Srs.round`가 깔고 `Store.ensureRound`가 자리를 저장하는 「오늘 복습」 판은 이미
하루 단위다. 자정에 새로 깔리고, 앱을 닫아도 이어 돈다. **새 카드만 안 들어간다** —
`round`가 `recOf(id)`가 있는 카드만 담기 때문이다. 거기에 새 단어를 넣는 것이 이
작업의 전부다.

## 대가를 화면에 적는다

N을 고르면 하루 푸는 장수가 따라온다. 슬라이더 밑에 그 자리에서 보여 준다:

| 하루 새 단어 | 손에 쥐는 카드 | 하루 푸는 장수 | 1,150개 끝나는 데 |
|---|---|---|---|
| 5 | ~50 | ~55 | 230일 |
| 10 | ~100 | ~110 | 115일 |
| 20 | ~200 | ~220 | 58일 |

공식은 `손에 쥐는 카드 = N × MASTERED_AT`, `하루 푸는 장수 = N × (MASTERED_AT + 1)`.
문턱을 상수에서 읽으므로 `MASTERED_AT`을 고치면 표도 따라온다.

20장은 하루 220장이다. 못 할 양은 아니지만 아침에 앉아서 끝낼 양은 아니다 —
숫자를 숨기면 사흘 뒤에 밀린 판을 보고 고장으로 읽는다.

## 무엇을 고치나

### `Settings` (Store.kt)

```
- var fresh: Int         (0..30, 기본 5)
- var review: Int        (0..30, 기본 20)
- var learningCap: Int   (5..60, 기본 20)
- val batch: Int get() = fresh + review
+ var daily: Int         (0..30, 기본 20)   // 하루 새 단어
```

- 저장 열쇠는 새로 판다(`set_daily`). 옛 열쇠 셋은 **읽지 않고 버린다** — `set_fresh`
  5장을 하루 몫 5장으로 옮기면 상한에 눌려 실제로는 하루 2장이던 사람이 갑자기
  5장이 되는데, 그 값은 사용자가 고른 적 없는 수다. 모두 기본 20장에서 시작한다.
- `0`을 허용한다. 새 단어를 끄고 복습만 하는 자리다 — 지금 `fresh = 0`이 하던 일이고
  「둘 다 0일 수 없다」는 가드는 슬라이더가 하나가 되면서 사라진다.
- 위 한계는 30으로 둔다. 30이면 하루 330장이라 그 위는 지킬 수 없는 약속이다.

### `Srs.round` — 새 단어를 판에 넣는다

지금은 기록 있는 카드만 담는다. 새 단어 `quota`장을 **쉬운 등급부터** 골라 앞에
붙이고 전체를 섞는다.

```kotlin
fun round(
    ids: List<String>,
    today: Long,
    quota: Int,                    // 오늘 남은 새 단어 몫
    levelOf: (String) -> Int,      // 등급 순서. 낮을수록 쉽다
    recOf: (String) -> Rec?
): List<String>
```

- 기록 없는 카드를 `levelOf` 오름차순으로 정렬해 앞에서 `quota`장 자른다. **같은
  등급 안에서는 섞는다** — 정렬만 하면 TSV 순서가 그대로 나와 한 분류가 며칠씩
  이어진다.
- 복습 카드는 지금 규칙 그대로(점수 낮은 순, 같은 점수면 오래 안 본 순).
- 마지막에 전체를 섞는다. 새 단어를 앞에 몰아 두면 중간에 그만뒀을 때 하필 복습만
  못 보고 끝난다 — `queue`가 이미 같은 이유로 섞는다.
- `quota`가 0이면 지금과 똑같이 복습만 나온다.

`levelOf`를 넘기는 이유: `Srs`는 `data/`의 순수 계산이라 `Word`·`Kana`를 몰라야
한다. 부르는 쪽(`Store`)이 카드 열쇠 → 등급 서수 함수를 준다. 한자·단어는
`Level.ordinal`(N5=0 … JOB=4), **가나는 -1**이라 N5보다 먼저 온다.

가나를 켜 둔 사람에게 아직 안 튼 가나가 남아 있으면 그것부터 다 나온다. 의도한
차례다 — 가나를 모르는 채로 단어를 외우는 순서는 없다. 이미 아는 사람은 기록이
있어서 애초에 새 카드가 아니고, 아예 안 볼 사람은 설정의 「복습 범위 → 가나」를
끄면 `activeCardIds`에서 통째로 빠진다.

### `Srs.queue` — `learningCap` 인자를 뺀다

```
- fun <T> queue(items, limit, today, freshQuota, learningCap, idOf, recOf)
+ fun <T> queue(items, limit, today, freshQuota, idOf, recOf)
```

`learning` 세기와 `if (learning >= learningCap) 0` 가지가 통째로 빠진다. `freshQuota`는
이제 **오늘 남은 몫**이다.

### `Srs.freshRoom` — 지운다

「아직」만 걸러 들어온 판을 상한으로 좁히던 함수다. 상한이 없어지면 좁힐 것이
하루 남은 몫 하나뿐이라 `minOf`가 필요 없다. `KanaScreen`·`WordQuizScreen`의 두
호출 자리는 `store.dailyLeft`로 바꾼다.

### `Store` — 남은 몫과 판 깔기

```kotlin
/** 오늘 남은 새 단어 몫. 자정에 freshToday가 0이 되므로 저절로 찬다. */
val dailyLeft: Int get() = (settings.daily - freshToday).coerceAtLeast(0)
```

- `wouldBe()`와 `newRound()`가 `Srs.round`에 `dailyLeft`를 넘긴다.
- `roundLeft`(홈·드로어의 남은 장수)는 판이 안 깔렸을 때 `countTodo`로 세기만 하는데,
  거기에 `dailyLeft`를 더한다 — 안 더하면 아침에 「오늘 공부 0」이 뜨고 눌러야
  새 단어가 나타난다.

### 화면

- **홈 단추·드로어**: 「오늘 복습」 → **「오늘 공부」**. 세는 수가 복습만이 아니게 된다.
- **`SettingsScreen`**: 「한 묶음 구성」 카드 → **「하루 목표」**. 슬라이더 하나와 위
  표의 해당 줄. 상한 설명문단 삭제.
- **`Parts.NothingDue`**: 상한 안내(`stage == NEW` 가지)를 「오늘 몫 N장을 다
  텄습니다 — 자정이 지나면 다시 오릅니다」로 바꾼다. `s.fresh == 0` 가지는
  `s.daily == 0`으로 이름만 바뀐다.
- **범위 연습**(단어 맞추기에서 N4·동사만): 묶음 크기 **20장 고정**(`Srs.DEFAULT_BATCH`).
  `settings.batch`가 없어지는 자리를 상수가 받는다. 새 단어 몫은 `dailyLeft`에서
  빌려오므로 **여기서 20개를 배우면 「오늘 공부」에는 새 단어가 안 뜬다** — 몫이
  한 벌이라 두 번 세지 않는다.

## 테스트

`Srs`가 순수 계산이라 JVM 단위 테스트가 그대로 잡는다. `SrsTest`에 붙인다:

- `round`가 몫만큼만 새 카드를 담는다 — 기록 없는 카드가 100장이어도 `quota = 20`이면 20장.
- `quota = 0`이면 새 카드가 한 장도 안 든다(복습만).
- 새 카드는 쉬운 등급부터 — N5가 몫보다 많으면 N4가 한 장도 안 든다.
- 같은 등급이 몫보다 많으면 뽑히는 장수만 맞고 어느 장인지는 고정이 아니다(섞인다).
- 복습 카드는 지금 순서 그대로 — 점수 낮은 순, 같은 점수면 오래 안 본 순.
- 챌린지로 치워 둔 카드(`isHeld`)와 오늘 통과한 카드는 여전히 빠진다.
- `queue`에서 `learningCap`이 빠져도 `freshQuota` 예약이 그대로 돈다.

`Store.dailyLeft`는 `Settings`가 `SharedPreferences`를 잡아서 JVM 테스트가 안 닿는다.
한 줄 뺄셈이라 그대로 둔다.

## 안 하는 것

- **옛 설정값 이사**: 위에 적은 대로 버린다.
- **복습 장수 상한**: 하루 220장이 많다고 자르면 밀린 카드가 영영 안 줄어든다.
  N을 낮추는 것이 그 조절이다.
- **범위 연습의 묶음 크기 슬라이더**: 상수 20으로 둔다. 설정을 하나로 줄이는 것이
  이 작업의 목적이라 다시 늘리지 않는다.
