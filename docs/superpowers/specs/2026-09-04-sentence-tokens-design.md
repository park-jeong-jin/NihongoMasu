# 예문 조각 눌러 보기 설계

2026-09-04

## 무엇을 만들었나

정답면의 예문에서 단어마다 밑줄이 붙고, 누르면 그 자리에 한 줄이 펴진다.

```
예문   車を貸していただけませんか。        ▶
       ‾‾   ‾‾
       くるまをかしていただけませんか。
       차를 빌려주시겠습니까?

       └ 貸し → 貸す · かす · 빌려주다     ▶
```

일본어는 띄어쓰기가 없어서 어디까지가 한 단어인지가 안 보인다. 그리고 예문에 나오는
꼴은 활용한 꼴이라(`貸し`) 사전에서 찾을 꼴(`貸す`)과 다르다. 둘 다 예문을 형태소로
끊어 두면 풀린다.

## 우리 단어표만으로는 안 된다

먼저 `vocab.tsv`의 표기 5,171개로 문장을 끊어 봤다. 가장 긴 것부터 맞추는 방식이고,
한자 글자를 덮는 비율이 **99.4%**로 나온다. 그런데 끊긴 것을 보면 못 쓴다.

| 문장 | 나온 결과 | 무엇이 틀렸나 |
|---|---|---|
| `私は韓国人です` | `韓` · `国` · `人` | 사전에 없는 `韓国人`이 낱자로 쪼개진다 |
| `何ですか` | `何で`(왜) | `何`+`です`+`か`인데 다른 단어로 잡힌다 |
| `行きます` | 기본형 `行き` | `行く`가 나와야 한다 |

덮는 비율은 높은데 틀린 자리가 학습자에게 그대로 가르쳐진다. **자신 있게 틀린 답은
아무것도 없는 것보다 나쁘다.** 그래서 이 방식은 버렸다.

## 분석기는 폰에 안 넣는다

형태소 분석기(kuromoji-ipadic)를 쓰면 위 셋이 다 정확해진다. 그런데 사전이 12.7MB라
APK가 9MB → 22MB가 된다. 단어 하나 눌러 보는 기능 값으로는 너무 비싸다.

**분석할 문장이 정해진 5,171개**라는 것이 답이다. 임의의 문장을 다룰 일이 없으므로
폰에서 분석할 것이 없다 — 여기서 한 번 돌려 결과만 싣는다.

| | |
|---|---|
| 생성 데이터 | 775KB (APK 안에서 180KB) |
| APK 크기 | 9MB → 9.2MB |
| 런타임 의존성 | 없음 |
| 손으로 쓸 데이터 | 없음 |

`tools/Tok.java`와 `tools/tokens.sh`가 그 일을 한다. 분석기 JAR은 gradle 캐시에
있으면 쓰고 없으면 받아서 `tools/.cache`에 둔다(git에 안 올린다). `vocab.tsv`의
예문을 고치면 `./tools/tokens.sh`를 다시 돌린다.

## 데이터 형식

`app/src/main/resources/tokens.tsv` — `표기 \t 토큰 토큰 토큰...`

토큰 하나는 `표면형:기본형:읽기:품사`다.

- 기본형·읽기가 표면형과 같으면 **비워 둔다.** 채워 두면 파일이 세 배가 된다
- 품사는 내용어(`名詞`·`動詞`·`形容詞`·`副詞`)에만 적는다. 빈 것은 조사·조동사·기호다
- 읽기는 가타카나를 히라가나로 옮겨 둔다. 화면이 후리가나로 쓴다

```
友達	友達::ともだち:名詞 と::: 映画::えいが:名詞 を::: 見:見る:み:動詞 ます::: 。:::
```

문장 5,171 · 토큰 47,573 · 내용어 22,069.

줄을 미리 다 쪼개 두지 않는다. 토큰이 47,573개라 앱을 켤 때마다 다 만들어 두면
화면에 한 번도 안 뜨는 것까지 만든다. 줄은 문자열로 들고 있다가 카드가 뜰 때 쪼갠다.

## 기본형에는 기본형의 읽기를 붙인다

분석기가 주는 읽기는 **문장에 쓰인 꼴의 읽기**다. 그것을 기본형 옆에 붙이면
`行く · いき`, `泊まる · とまり`가 된다 — `行く`는 `いく`다. 만들면서 실기기에서
이 버그를 보고 고쳤다.

기본형의 읽기는 **우리 단어표에서** 뗀다. 활용한 내용어 5,433개 중 3,907개(71.9%)가
여기서 잡히고, 안 잡히는 것은 읽기를 아예 안 보여준다. 쓰인 꼴의 읽기는 바로 위
「예문 읽기」 줄에 이미 있다.

## 화면

**표시는 밑줄이다.** 각진 바탕·둥근 바탕·밑줄을 다 만들어 실기기에서 견주고 골랐다.
바탕은 상자가 글자를 꽉 채워 문장보다 상자가 먼저 보인다. 밑줄은 문장이 문장으로
읽히면서 경계가 보이고, 글에서 밑줄은 원래 눌리는 것을 뜻한다.

밑줄을 글자 배치(`TextLayoutResult`)를 받아 뒤에 직접 그린다.
`TextDecoration.Underline`은 글자색을 따라가 색을 따로 줄 수 없어서, 눌린 조각만
진하게 둘 방법이 없다. 한 조각이 줄바꿈에 걸리면 줄마다 따로 그린다.

**누를 수 있는 것은 뜻을 말해 줄 수 있는 조각뿐이다.** 기본형이 다르다는 것만으로
받으면 `い`(→`いる`)·`ん`처럼 우리 사전에 없는 문법 요소가 눌려서, `い → いる`만
뜨는 자리가 생긴다. 배울 것은 없는데 칸은 차지한다. 내용어의 78.3%가 여기 걸리고,
나머지(`いる`·`ある`·`の`·`こと`·`よう`)는 조사처럼 회색으로 남는다.

뜻은 단어표에서 먼저 찾고, 없으면 한 글자짜리 한자를 한자표에서 찾는다. 뒤쪽은
0.6%p밖에 안 보태지만 낱자 뜻이라도 있는 편이 아무것도 없는 것보다 낫다.

**나란히 붙은 조각 사이에만 얇은 공백**(`U+2009`)을 넣는다. 밑줄이 이어지면 둘이 한
단어로 보인다 — `全然分かり`의 `全然`과 `分かり`. 조각마다 다 띄우는 것도 해 봤는데
`遊ん で い ます`처럼 조동사까지 떨어져 문장이 부서졌다. 조사는 회색이라 그것만으로
이미 갈린다.

**칩을 늘어놓지 않는다.** 글 한 줄로 둔다 — 칸으로 쪼개면 줄바꿈이 칸 단위로 일어나
읽는 흐름이 끊긴다.

## 어디에 붙나

`ui/Face.kt` 하나만 고쳤다. 예문을 그리는 자리가 거기뿐이라 **단어 맞추기 · 한자
맞추기 · 문장 맞추기 · 오답 노트**의 정답면이 한꺼번에 얻는다. 「같은 카드의 뒷면은
어디서 보든 같아야 한다」는 그 파일의 원칙 그대로다.

`Say`에 `tokens`가 붙었다. 있으면 `text` 위에 눌러 볼 수 있는 일본어 줄이 서고
`text`에는 읽기와 뜻만 담는다 — 일본어 줄을 두 군데서 그리지 않는다.

## 검사

`TokensTest` 여섯 개. 이 표는 손으로 적은 것이 아니라 생성물이므로, 볼 것은
「데이터가 맞나」가 아니라 **「생성기와 읽는 쪽이 맞물리나」**다.

- 모든 단어에 끊어 둔 예문이 있는지
- **조각을 이어 붙이면 예문이 그대로 나오는지** — 콜론으로 네 칸을 가르는 형식이라
  표면형에 콜론이 섞이거나 칸이 밀리면 문장이 조용히 망가진다. 제일 중요한 검사다
- 조각 수가 유지되는지 (47,573 · 22,069)
- 내용어에 뜻이 붙는 비율이 78% 아래로 안 떨어지는지
- `行き`의 기본형 읽기가 `いく`인지 (`いき`가 아닌지)
- 조사와 기호가 내용어로 안 잡히는지

## 일부러 안 하는 것

| 안 하는 것 | 이유 |
|---|---|
| 분석기를 APK에 넣기 | 12.7MB. 문장이 정해져 있어 폰에서 분석할 일이 없다 |
| 우리 단어표로 문장 끊기 | 99.4%를 덮지만 `韓国人`·`何ですか`·`行きます`에서 틀린다 |
| 조사도 누를 수 있게 | 뜻도 기본형도 없어 눌러도 할 말이 없다. 경계는 밑줄로 이미 보인다 |
| 문장 맞추기의 **문제면**에 붙이기 | 빈칸 문제에 힌트가 늘어난다. 정답면에만 둔다 |
| 눌러서 그 단어 카드로 건너가기 | 돌던 묶음이 날아간다. 「든 한자」 칩이 안 건너가는 것과 같은 이유다 |
| 조각마다 다 띄우기 | `遊ん で い ます`가 되어 문장이 부서진다 |
