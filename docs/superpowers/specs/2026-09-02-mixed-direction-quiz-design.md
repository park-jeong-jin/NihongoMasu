# 랜덤 방향 맞추기 · 스피드 분리 · 써보기 제거

2026-09-02

## 무엇을 하려는 것인가

지금 앱의 모든 방향은 **일본어를 보여주고 시작**한다. 「전철」을 보고 `電車`를 떠올리지
못해도 익힘까지 오를 수 있다. 인식(recognition)만 촘촘하고 산출(production)이 비어 있다.

그래서 방향을 하나 늘리고, 카드마다 방향이 **랜덤으로** 정해지게 한다. 같이 딸려 오는
정리가 셋 있다 — 써보기 제거, 스피드 분리, 듣기·빈칸 제거.

## 사용자가 보는 것

메뉴: `오늘` · `가나 맞추기` · `단어 맞추기` · **`스피드`** · `오답 노트` — `찾기` · `설정`

| | 지금 | 바뀐 뒤 |
|---|---|---|
| 가나 맞추기 | 서체 → 방식 4개 토글 | 서체 → **즉시 섞인 세션** (로마자↔듣고 쓰기) |
| 단어 맞추기 | 방향 3개 토글 (뜻·듣기·빈칸) | 범위 누를 때 **팝업** (일→한 · 한→일 · 일↔한) |
| 스피드 | 가나 맞추기 안의 네 번째 탭 | **최상단 메뉴** → 히라가나 / 가타카나 / 단어 |
| 써보기 | 있음 | 없음 |
| 듣기 · 빈칸 | 있음 | 없음 |

## 1. 섞기 — 중복 제거가 이미 하고 있다

`Srs.queue`의 `fill`이 `seen.add(idOf(item))`으로 열쇠 중복을 걸러낸다. 통에 방향별로
한 장씩 넣고 열쇠를 방향과 무관하게 뽑으면, 버킷이 이미 섞인 뒤라 **살아남는 쪽이
랜덤으로 정해진다.** `Srs`도 `Store`도 안 건드린다.

```kotlin
// 가나 — 방식이 달라도 기록은 한 벌 (Kana.id는 서체만 본다)
val pool = KanaData.all.flatMap { k -> KanaAsk.entries.map { KanaCard(k, it) } }
val idOf = { c: KanaCard -> c.kana.id(script) }
```

단어·한자도 같다. `Ask.MIX`가 통에 두 방향을 다 넣고, 열쇠가 같아 카드마다 하나만
살아남는다. 지금 빈칸이 뜻과 열쇠를 공유하는 방식과 똑같고, 그 선례가 코드에 이미 있다.

```kotlin
enum class Ask(val label: String) {
    SHOW("일→한"), RECALL("한→일"), MIX("일↔한");

    /** MIX는 통에 둘 다 넣는다. 열쇠가 같아 Srs.queue가 카드마다 하나만 남긴다. */
    fun faces(): List<Ask> = if (this == MIX) listOf(SHOW, RECALL) else listOf(this)
}
```

### 반드시 함께 고쳐야 하는 것 — Srs.requeue

`requeue`의 자리채우개가 `queue.toHashSet()`으로 `T` 동등성을 본다. 방향이 카드에
실리면 `あ`(로마자)가 큐에 있는데 `あ`(듣고 쓰기)를 새 카드로 끌어온다 — 같은 글자가
한 묶음에 두 번. 열쇠로 보게 바꾼다.

```kotlin
val seen = queue.mapTo(HashSet()) { idOf(it) }
val fill = pool.filter { idOf(it) !in seen && recOf(it) != null }
```

`idOf: (T) -> String` 파라미터 하나 추가. 프로덕션 호출부는 `QuizSession.record` 한
곳뿐이고 거기엔 이미 `idOf`가 있다. 기존 테스트가 위치 인자를 쓰므로 기본값을
`{ it.toString() }`으로 둔다.

## 2. 듣기·빈칸 제거가 무너뜨리는 것

`Ask`의 세 항목이 모두 같은 기록 열쇠를 쓰므로 **접미사 개념 자체가 없어진다.**

```kotlin
fun studyIds(scripts: List<Script>): List<String>   // cardIds()와 완전히 동일해짐 → 삭제
fun QuizMode.suffixes(kind: CardKind)               // → 삭제
```

| | 지금 | 바뀐 뒤 |
|---|---|---|
| 복습 대상 | 12,612개 (방향까지 셈) | 6,410개 = 글자·단어 수 그대로 |
| 「오늘 복습 30개」 | 방향 포함 30개 | 실제 카드 30장 |
| 익힘 비율 분모 | 카드용·복습용 두 벌 | 한 벌 |

빈칸을 지워도 데이터 손실은 0이다 — 뜻과 기록을 공유했으므로. `Word.clozed()`에 남아
있던 알려진 결함(어간으로 지울 때 예문의 다른 낱말까지 뚫림)도 함께 사라진다. 예문은
정답면에 그대로 남는다.

듣기를 지우면 소리→뜻 능동 청해를 잃는다. 소리 자체는 정답면의 줄별 재생 단추로 남아
「발음 확인」은 그대로다. TTS는 가나 듣고 쓰기가 계속 쓴다.

**감수하는 것**: 산출(한→일)이 인식(일→한)보다 어려운데 같은 상자를 쓰므로 일정이
산출 실력을 살짝 과대평가한다. 직접 채점이라 어렵게 느끼면 낮게 주면 된다.

## 3. 방향은 한 곳에서만 고른다

지금 방향 토글은 누르면 `LaunchedEffect(kind, tag, mode) { rebuild() }`로 **묶음이 통째로
다시 깔린다.** 판 도중 전환이 아니라 새 판 시작이다. 그러면 그 선택은 판이 시작되는
자리 — 범위를 누르는 그 순간에 있는 것이 정직하다.

```
┌─ N5 한자 · 무엇을 물을까요? ────────┐
│  일→한    電車 → 전철·でんしゃ      │
│  한→일    전철 → 電車               │
│  일↔한    둘을 카드마다 섞어서      │
└─────────────────────────────────────┘
```

설정에는 같은 목록에 맨 위 한 줄을 더한다: `그때그때 고르기`(기본) · 일→한 · 한→일 ·
일↔한. `그때그때 고르기`면 범위를 누를 때 팝업이 뜨고, 고정해 두면 팝업 없이 바로
그 방향으로 들어간다.

기본값을 `그때그때 고르기`로 두는 이유는, 고정값을 기본으로 하면 다른 방향 한 번
해보려고 설정에 들어가야 하기 때문이다. 매번 같은 것을 고르는 사람은 자연히 설정에서
고정하게 된다.

네 줄이면 `SegmentedRow`에 들어갈 것 같지만 안 된다 — 균등 분할이라 360dp에서 한 칸이
90dp인데 「그때그때 고르기」가 13sp로 그 폭을 넘는다. 세로 목록으로 간다.

세로 목록은 부품 하나(`AskList`)로 만들어 팝업과 설정이 함께 쓴다 — 목록이 두 군데서
어긋날 자리를 없앤다. `AlertDialog`는 `ConfirmDialog`가 이미 쓰고 있어 새로 들이는
것이 아니다. 이 앱에 `DropdownMenu`는 한 개도 없고 앞으로도 안 쓴다.

가나에는 팝업이 없다. 로마자와 듣고 쓰기가 **기록을 한 벌 쓰므로** 고를 이유가 없다.
단어는 방향마다 물음이 다르고 산출이 별개 능력이라 고를 이유가 있다.

### 정답면 배치

`Face`가 방향에 따라 이렇게 채워진다. 질문면과 같은 값은 비워 둔다.

| | `prompt` | `answer` | `meaning` |
|---|---|---|---|
| 단어 SHOW | `w.w` | (비움) | `w.mean` |
| 단어 RECALL | `w.mean` | `w.w` | (비움 — 질문면에 이미 있다) |
| 한자 SHOW | `k.c` | (비움) | `k.mean` |
| 한자 RECALL | `k.mean` | `k.c` | (비움) |

`RECALL`의 질문면은 한국어라 `JpText`가 아니라 일반 `Text`로 그린다. `JpText`는 일본어
서체를 물리므로 한글이 들어가면 대체 글꼴로 떨어진다.

읽기·예문·음독·훈독 줄들(`says`)과 이어보기(`link`)는 방향과 무관하게 그대로다 —
정답을 본 뒤에 나오는 것이라 어느 쪽에서 왔든 같아야 한다.

## 4. 가나 세션을 KanaFlow로 올린다

지금 `RomajiBody`·`DictationBody`가 각자 세션·큐·「한 바퀴 마침」·되돌리기를 들고 있다.
한 세션이 두 방식에 걸쳐야 하므로 위로 올린다.

```kotlin
// KanaFlow — 세션·헤더·마침 화면을 여기서 한 번만
val session = rememberQuizSession(store, { c: KanaCard -> c.kana.id(script) }) { pool }
when (session.card?.ask) {
    KanaAsk.ROMAJI    -> RomajiCard(session, card, script)
    KanaAsk.DICTATION -> DictationCard(session, card, script, speaker)
}
```

두 `Card`는 자기 입력 위젯과 채점만 맡는다. 공용 껍데기(`QuizHeader`·`CycleDone`·
`NothingDue`·되돌리기)가 두 파일에서 빠져 위로 올라가므로, 지금 있는 중복이 줄어든다.

`KanaAsk`에 `label`은 두지 않는다 — 화면에 방식 이름이 뜨지 않고, 자판이 나오는지
캔버스가 나오는지로 보면 안다.

## 5. 스피드

`Feature`에 `SPEED("스피드")` 한 줄. 기존 `Menu → Practice` 두 단계가 그대로 맞는다 —
메뉴에서 히라가나/가타카나/단어를 고르고 들어가 판을 돈다. 설정에서 가나를 끄면
스피드 메뉴에서도 히라·가타 두 줄이 빠진다(`featuresOf`와 같은 논리).

`Store.speedBest(script)` → `speedBest(key: String)`. 키는 `"hira"`·`"kata"`·`"word"`.
저장 키가 이미 `"speed_" + name.lowercase()`라 기존 최고점이 그대로 이어진다.

### 단어 스피드

- **대상**: 한 번이라도 맞힌 단어 (`(store.get(w.id)?.ok ?: 0) >= 1`).
  방향별 기록이 없어졌으므로 단어 한 장에 열쇠 하나다
- **문제**: 표기 → 한국어 뜻 4지선다. 탭 하나로 넘어간다
- **기록**: 가나 스피드와 같다 — 복습 기록을 건드리지 않고 최고 점수 하나만
- **대상 0장**: 시작 화면에서 "아직 맞춘 단어가 없습니다" + 단어 맞추기로 보내기

읽기 타이핑은 쓰지 않는다. 가나 스피드는 `RomajiCheck.matches(input, kana)`가 한 글자
대 한 글자라 표가 그대로 답인데, 단어 읽기를 로마자로 받으려면 가나열→로마자 변환기가
필요하다. `KanaData` 104행에 `っ`도 `ー`도 없어 `がっこう`·`コーヒー`에서 바로 막히고,
헵번 촉음 규칙과 `ん` 뒤 자음 처리를 새로 짜야 한다. 게다가 60초에 단어를 통째로
타이핑하면 열 장을 못 넘겨 「스피드」가 성립하지 않는다.

오답 뽑기는 순수 함수로 둔다:

```kotlin
/** 같은 분류 → 같은 등급 → 전체 순으로 채운다. 정답과 뜻이 같은 것은 뺀다. */
fun VocabData.distractors(answer: Word, n: Int = 3): List<Word>
```

같은 분류에서 먼저 뽑는 이유는 변별력이다. 「은행」의 오답이 「달리다」면 뜻을 몰라도
찍힌다. 대신 동의어가 오답으로 오면 억울하므로 뜻이 같은 것은 제외한다.

## 7. 기존 기록

- `L` 접미사 기록은 고아가 된다. 지우지 않고 백업 파일에도 남으므로 되살리면 돌아온다
- 「복습 대기」 숫자가 반 이하로 뚝 떨어진다. 방향을 세지 않게 되어서다 — 정상이다
- 스피드 최고점은 저장 키가 같아 그대로 이어진다
- 저장·백업 JSON 형식은 안 바뀐다

## 8. 테스트

추가:

1. 섞인 통에서 같은 열쇠가 한 번만 나오고, 여러 번 돌리면 방향이 갈린다
2. `requeue`가 열쇠 같은 다른 방향 카드를 자리채우개로 끌어오지 않는다 — 위 수정의 회귀 방지
3. `distractors`가 정답·동의어를 내지 않고 3장을 채운다

정리:

- `DataTest`의 빈칸 뚫림 테스트 삭제
- `DataTest`의 `studyIds` 테스트 3개를 `cardIds` 쪽으로 통합
- `SrsTest`의 `Srs.trace` 테스트는 남는다 (듣고 쓰기가 계속 쓴다)

## 9. 작업 순서

지우는 것을 먼저 한다. 표면을 줄여 놓고 손대야 헛일이 없다 — 써보기가 남아 있는 채로
가나 세션을 올리면 곧 지울 화면 하나를 새 구조에 맞춰 고치게 된다.

1. **써보기 제거** — `TraceScreen.kt`, `KanaMode.TRACE`, 슬라이더·안내선, `Store.trace`,
   `WritingBox`의 `guide`
2. **듣기·빈칸 제거와 `Ask` 도입** — `QuizMode` → `Ask`, `studyIds()` 삭제,
   `Word.clozed()` 삭제, `Face` 재배치. 이 단계에서 테스트가 여러 개 정리된다
3. **`Srs.requeue`에 `idOf`** — 다음 두 단계가 이것 없이는 같은 카드를 두 번 낸다
4. **팝업과 설정** — `AskList` 부품, `Settings.ask`, `WordQuizFlow`의 `pending` 상태
5. **가나 세션 올리기** — `KanaFlow`로 세션·껍데기 이동, `RomajiCard`·`DictationCard`
6. **스피드 분리** — `Feature.SPEED`, `speedBest(key)`, 단어 스피드와 `distractors`
7. **README**

3번이 5번보다 앞에 있는 이유는, 가나 섞기가 자리채우개로 같은 글자를 두 번 끌어오는
것을 먼저 막아야 5번을 손으로 검증할 수 있기 때문이다.
